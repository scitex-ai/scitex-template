# Directory Structure

```
my_project/
├── config/              # parameters (MNIST, STATS, FIGURE, CLAIMS, SCHOLAR, HPC) + PATH.yaml
├── scripts/
│   ├── mnist/           # the showcase: 00_resolve_references ... 05_register_claims
│   ├── demo/            # planted-fault demo (make demo-fault)
│   ├── hpc/             # optional Slurm dispatch (make hpc)
│   └── template.py      # starting point for a new script
├── notebooks/           # notebook variant of one step (make notebook)
├── manuscript -> .scitex/writer   # alias of the writer workspace holding the paper's text
├── data/                # links to script outputs (scripts/**/<script>_out/)
├── container/           # optional Apptainer definition (make container)
├── tests/scripts/       # tests mirroring scripts/
├── .scitex/             # dev config + manuscript text in writer/ (committed); clew state + writer engine (not committed)
└── Makefile             # all / live-paper / verify / demo-fault / lint / test
```

## Outputs and links

`sio.save(obj, "./data/x/y.json", symlink_from_cwd=True)` called from
`scripts/mnist/02_train.py` writes `scripts/mnist/02_train_out/data/x/y.json`
and links `data/x/y.json` to it (a relative link). Clew records the real
file as an output of that run, so `data/` is a flat, stable view whose every
file traces back to the run that wrote it.

## Committed vs regenerated

Everything under `*_out/`, `data/` and `.scitex/` is regenerated by
`make all`, except the resolved bibliography
(`scripts/mnist/00_resolve_references_out/data/literature/` and its
`data/literature/` links): `make refs` is the one online step, so its result
is committed together with the record of how it was produced.
